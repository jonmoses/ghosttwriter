Ghosttwriter

What this project is. Rewritten by ship; never appended.

Purpose

Ghosttwriter is a macOS-only fork of Ghostty for one person running several Claude Code sessions side by side. The Zig terminal core is unchanged; the Swift app adds a workbench around it: a vertical tab sidebar grouped by git repo with color, directory, git and Claude status on each row; a per-session goals panel that both the user and Claude write to, with every change logged; a resume dashboard that keeps closed Claude sessions with a "still to finish" note; and a side pane per tab for HTML, Markdown and PDF, with small HTML shown as an inline snapshot card. User guide: docs/ghosttwriter.md.

How the pieces talk

Claude reaches the app only through gtw, bundled at Contents/MacOS/gtw and on PATH in every shell. The claude-plugin hooks (SessionStart, UserPromptSubmit, PostToolUse, Notification, Stop, SessionEnd) pipe Claude's hook JSON into gtw hook, and Claude's Bash tool runs gtw goal, gtw note and gtw show directly. gtw knows its tab from GHOSTTWRITER_SURFACE, which the app sets in each surface's environment along with TABCOLOR and GHOSTTWRITER_SOCKET, and sends one newline-terminated JSON request (protocol v1, types in WorkbenchProtocol) per connection to gtw.sock. ControlServer dispatches each request to WorkbenchStore on the main actor; the store attaches Claude sessions to surfaces, advances the status machine (idle, waiting, working, needs_input; done is derived from goals), and mirrors everything to state.db. Every view (sidebar, goals panel, side pane, snapshot cards, resume dashboard) observes the store, and the sidebar drives Ghostty's native tab group only through TabGroupBridge. Closing a tab detaches its session record (after the "Still to finish?" sheet for a busy session); the dashboard reattaches it to a new tab that types claude --resume <id>.
